## 2. 電腦端恢復使用

在解壓縮後的根目錄開啟終端機，使用原本的 Python 環境：

```bash
python pc_dashboard.py
```

這四個電腦端檔案都有使用關係，請一起保留。早期的 `from_jetson_orin_nano` 接收程式已放在歷史資料中，不是目前統一操作介面的入口。

既定電腦位址仍為 `192.0.2.10`，網路連線與穿透方式沿用原設定。這份復原包不包含你電腦上已安裝的 Python 環境；若只是專案資料夾遺失，直接使用原本環境即可。

## 3. Jetson 是否需要重新放檔案

如果 Jetson 上的原專案與環境仍在，這次只恢復電腦資料夾即可，不必為此重新安裝 Jetson。

若 Jetson 的專案也需要恢復，將本包 `jetson orin nano` 資料夾內的內容放到：

```bash
$HOME/Desktop/jetson orin nano
```

確認 `minitesla.py` 直接位於該目錄，避免形成兩層同名資料夾。若原服務還在執行，先在原專案目錄執行 `python3 minitesla_service.py stop`，再覆蓋檔案。

完成複製後，先啟用原本的 Python 環境，以一般使用者執行：

```bash
cd "$HOME/Desktop/jetson orin nano"
chmod +x rplidar_sdk-master/output/Linux/Release/ultra_simple
```

若原服務仍已安裝，而且專案位置與 Python 環境都沒變：

```bash
python3 minitesla_service.py restart
python3 minitesla_service.py status
```

若服務尚未安裝，或專案位置／Python 環境已改變，改用：

```bash
python3 minitesla_service.py install --pc-host 192.0.2.10
python3 minitesla_service.py status
```

安裝指令會安裝、啟用並啟動原有開機服務；需要系統權限時，工具會自行呼叫 `sudo`。不要用 `sudo python3` 啟動安裝工具，也不要同時另外啟動第二份車端主程式。雷達預設裝置沿用 `/dev/ttyUSB0`。

封裝時已補回雷達執行檔權限；經過 Windows 解壓縮、複製後仍可能遺失權限，因此保留上面的 `chmod +x` 步驟。雷達執行檔為原上傳的 64 位元 ARM（AArch64）版本，不是本次重新編譯。

## 4. M4 工程恢復

使用原本的 Keil 開啟：

```text
wheelcontrol(main)/MDK-ARM/wheelcontrol.uvprojx
```

目前 `Core/Src/main.c` 是第一、二階段正式更新包內的四向測距版本，含 79 位元組遙測封包；後續第三至第十階段沒有再覆蓋 M4 程式。

如果板上仍是原本正常運作的韌體，僅恢復檔案不需要重燒。若要重新燒錄，先在原本的 Keil 環境執行完整重建（Rebuild），再使用本次建置的結果。歷史資料夾中的舊 `.hex`、`.axf` 不能視為目前原始碼的編譯結果。

## 5. 目前程式版本與操作

目前整併至第十階段：「巡邏 → 找到車位 → 停止並通知 → 限時決定 → 同意後自動入庫」。

| 操作 | 行為 |
| --- | --- |
| 空白鍵後按 G | 開始巡邏找位任務 |
| 通知出現後按 Y | 同意該車位，重新確認並規劃入庫 |
| 通知出現後按 N | 略過，依原規則繼續找位 |
| 沒有回覆 | 決定期限結束後停止待命 |
| 空白鍵 | 結束任務、停止待命 |
| P | 原本的反應式巡邏 |
| K | 從目前位置辨識車位並直接入庫，不經詢問流程 |

完整期限、故障處理與操作細節見 `復原說明/歷次更新說明/12_MiniTesla_Phase10_Mission_Update_v1.md`。各階段說明中的「套用更新」是當時的增量更新操作，本復原包已完成合併，無須再做一次。

推論仍使用 `best.pt`。車輛及停車幾何參數仍寫在 `minitesla_sensors/vehicle_config.py`，不需每次啟動輸入；舊 `parking_config.json` 已移到歷史資料。
