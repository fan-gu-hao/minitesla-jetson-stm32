# MiniTesla 第九階段 v2：車輛資料直接寫死

此包是第九階段 v1 的增量更新：現場量好後，把資料直接寫進 `minitesla_sensors/vehicle_config.py`，之後開機讀取固定值，不在執行時詢問。自動停車功能仍是：**車子原地辨識目前雷達可見的三面實體車位，選擇車位、規劃前進／倒車路徑、轉向對位，再倒車停入。** 不需要人工先把車身對正，但必須先位於能觀察車位、且有可行進退空間的位置。

此版不包含「看不到車位時自行巡航探索整個房間」，也不辨識僅畫在地面的車位線。原有巡邏模式仍獨立使用。

## 1. 只提供這次有改動的檔案

本包須先套用第九階段 v1，不是完整專案。共 5 個檔案：

| 檔案 | 操作／作用 |
| --- | --- |
| `Jetson/minitesla_sensors/vehicle_config.py` | 新增；唯一的固定車輛、雷達、轉向與停車參數來源 |
| `Jetson/minitesla_sensors/parking_config.py` | 覆蓋；讀取固定值，保留範圍與幾何驗證 |
| `Jetson/minitesla.py` | 覆蓋；啟動時一律載入固定參數 |
| `Jetson/parking_setup.py` | 覆蓋；只保留狀態與不移動車輛的預覽 |
| `README_使用說明.md` | 覆蓋；本版操作說明 |

沒有重複附上未修改的 PC、M4、停車演算法、模型或驅動；這些仍需保留原檔。沒有新增套件。IP 仍為 `192.0.2.10`。

舊 `Jetson/parking_config.json` 已不再使用；可以刪除。即使留著、內容過期或損壞，也不會覆蓋固定設定；刪掉它也不會退回舊版直線倒車。其他 `sensor_config.json` 等原檔仍要保留。

## 2. 現場量好後，直接編輯一次

先停止 Jetson 服務，再把壓縮包 `Jetson` 底下的檔案合併至車端原資料夾：

```bash
cd "$HOME/Desktop/jetson orin nano"
python3 minitesla_service.py stop
```

用文字編輯器開啟 `minitesla_sensors/vehicle_config.py`。所有停車參數集中在 `VEHICLE_SETTINGS` 字典。量好就直接改數字並保存，不需執行 `configure`、`set` 或 `enable`；這些舊指令已移除。

以下五個欄位目前仍是 `None`，因為現有資料沒有本車的確定數值：

| 欄位 | 要寫入的實測值 |
| --- | --- |
| `lidar_yaw_deg` | 雷達原始 0° 對應的車體方向，單位度；向前 0°、向右 +90°、向後 ±180° |
| `lidar_y_from_center_m` | 雷達旋轉中心相對**車身中心線**的橫向距離，右正左負，單位公尺；置中為 `0.0` |
| `rear_overhang_m` | 車尾至後軸中心距離，單位公尺，不是軸距 |
| `left_turn_radius_m` | 使用 `steering_left_pwm`（目前 128）時，**後軸中心**軌跡的左轉半徑，單位公尺 |
| `right_turn_radius_m` | 使用 `steering_right_pwm`（目前 176）時，**後軸中心**軌跡的右轉半徑，單位公尺 |

長度一律使用公尺，例如量到 100 毫米就寫 `0.100`；這只是單位示例，不是本車實測值。PWM 數值不是角度。左右轉彎半徑可不同；若改動轉向 PWM，也要更新對應半徑。

雷達朝向可由固定物體的原始角度決定：若車正前方物體的原始角度為 A，順時針遞增時 `lidar_yaw_deg` 為 −A；逆時針則為 +A，將結果折回 −180°～180°。同時把 `lidar_clockwise` 填為 `True`（順時針）或 `False`（逆時針）。這是安裝角度的設定，不是每次行駛輸入。

原資料有雷達 `y=181 mm`，但其橫向原點不明，因此保留待填。若它確實由左車緣量起，且車寬為 328 mm，中心線偏移才是 `181−164=17 mm`；不能把這個條件式例子當成已確認值。

其他沿用值也在同一個檔案，可以現場量好後直接改：

| 欄位 | 目前固定值 | 定義 |
| --- | --- | --- |
| `body_length_m` | `0.474` | 整車外框長度 |
| `body_width_m` | `0.328` | 整車外框寬度 |
| `wheelbase_m` | `0.275` | 前後軸距 |
| `lidar_x_from_tail_m` | `0.300` | 車尾向前至雷達旋轉中心 |
| `bay_width_m` | `1.6` | 實體車位內寬，換場地時修改 |
| `bay_depth_m` | `1.8` | 實體車位內深，換場地時修改 |

填妥後，把同一檔案頂端字典內的 `"enabled": False` 改為 `"enabled": True` 並保存。它只開放 K 停車指令，開機仍為待命。若先不填，保持 `False` 即可繼續手動與巡邏；K 會停用。啟用但仍缺值或數值不合法，會在開啟硬體前報錯並指出這個檔案，不會改用猜測值。

可選擇核對檔案內容：

```bash
python3 parking_setup.py status
```

此指令只顯示資料，不要求輸入、不儲存任何設定，也不是每次開機必跑的步驟。固定幾何完整時，主程式會同步更新共用雷達的方向與水平位置；原本雷達 Z 高度保留。

**每次修改固定檔案後，都必須重啟服務才會生效。** 開機自動執行沿用原服務，不會出現問答流程；若程式還在執行，編輯檔案不會即時改變行駛中的參數。請先重啟，再使用路徑預覽或 K，避免舊程序與新檔案不同步。

## 3. 先看不會移動車輛的預覽

擺放三面固定擋板形成 U 形車位，入口朝走道。擋板必須高於雷達實際掃描平面；依目前配置約離地 315 毫米，不可只在地上貼膠帶或放低於掃描面的物體。

入口、兩側牆及後牆需要能被雷達觀察。開始時可以有車身角度，但遮住大部分車位、背後只有未知空間、或看不到足夠牆面時，程式會拒絕規劃。車位外也需要供車頭和車尾轉動的空間。

若要先搭一組展示場景，下列是已通過理想幾何模擬的配置，可作為起點；使用時將車位寬深設定改為相同尺寸，不沿用預設寬深：

| 項目 | 模擬配置 |
| --- | --- |
| 車位內寬／內深 | 1.8／1.3 公尺，兩側與後方有實體擋板 |
| 周圍封閉空間 | 長 3.4 公尺、寬 2.8 公尺；以車位後牆中央為原點，X 為 −0.5～2.9、Y 為 −1.4～1.4 公尺 |
| 起始後軸中心 | 約 X=1.925、Y=0 公尺，車頭相對入口外向轉 90° |
| 模擬轉彎半徑 | 左右均 0.65 公尺，**這是模擬條件，不是你的實車校正值** |
| 到位目標 | 後軸中心 X=0.7、Y=0、車頭朝入口外；模擬後懸長 0.1 公尺 |

上述場景的六種相近起姿都完成倒入，四向測距在每 5 毫秒模擬子步均介於約 651～1913 毫米。此結果使用理想牆面回波與車輛運動模型，不代表任意安裝、材質、地面摩擦或轉彎半徑都會得到相同結果。

先啟動車端及既有電腦端視窗：

```bash
python3 minitesla_service.py start
```

電腦端沿用：

```bash
python pc_dashboard.py
```

在操作台按空白鍵，確認車端處於待命。Jetson 執行：

```bash
python3 parking_setup.py preview
```

會在 Jetson 專案資料夾產生 `parking_preview.svg`。以瀏覽器開啟，或複製到電腦觀看：灰點是實際回波、青色路徑是前進、紫色是倒車、橘框是目前車體。

這個工具只讀取目前感測快照，**不開啟 UART、不傳送控制命令、不啟用停車**。快照過期、車端不在待命或設定不完整時會拒絕產生預覽。即使顯示可行路徑，正式按 K 時也會重新讀取感測資料並重新規劃，不沿用預覽檔。

若你改過快照路徑，可用：

```bash
python3 parking_setup.py preview --help
```

## 4. 啟用與正式操作

參數已在檔案寫好且 `enabled=True` 後，重啟：

```bash
python3 minitesla_service.py restart
```

不需要重新安裝服務。電腦端仍只有一個 `pc_dashboard.py`，操作差異是：

1. 先按空白鍵回待命。
2. 按 **K：自動找位入庫**。
3. 觀察狀態依序進入尋位、位置穩定確認、路徑規劃、前進調整／倒車及中立換向、停妥確認。
4. 成功後回待命，顯示入庫完成。

實際進退次序由路徑決定，可能需要先小幅倒退、再前進轉向、最後倒入；不是每次都固定前進一次再倒車一次。最後到位的路段必須是倒車。

右欄顯示目前／最後位置、目標位置、角度和目前路段剩餘距離。座標原點是車位後牆中央，X 朝入口外方、Y 向左；它與原感測檔的「車尾原點、Y 向右」不同，程式會做明確轉換。

空白鍵、手動接管、失去操作視窗焦點、縮小視窗與斷線處理都沿用既有規則。中止後不會自動重試或繼續行駛，需要回到待命再按 K。自行巡邏與停車仍為不同模式，不會在巡邏中默默切換成停車。

要暫時停用新增停車功能，直接把 `vehicle_config.py` 的 `enabled` 改為 `False`，再執行：

```bash
python3 minitesla_service.py restart
```

停用後 K 不可用，手動與巡邏照常。本版一律使用固定設定，不依舊 JSON 檔存在與否切換停車模式。

## 5. 會停止的情況與場地限制

- 保留現有 M4 保護；Jetson 在停車模式另要求四向 ToF 都有效且大於 450 毫米。不能把無效測距當成空曠。
- VL53L0X 的距離能力會限制場地。周圍太空曠、某一方向沒有有效反射面，也可能無法入庫；不能因雷達能看到更遠，就忽略該方向 ToF 失效。
- 雷達需要持續看到足夠不同方向的牆面。遮住後牆、只有兩面平行牆、位置突然跳變或出現多個無法區分的追蹤解，都會停止。
- 不把缺少回波的地方當作可行駛空間；障礙後方的遮蔽區也不能直接穿越。
- 轉向時檢查的是整個車體及其掃過區域，不只有車身中心點。
- 路徑偏差過大、沒有進展、定位變化超出限制、規劃或整體任務逾時，都會回中立並中止。
- 規劃完成後重新取得新掃描，才允許開始移動；計算前的舊掃描不能包裝成新命令。
- 目前沒有輪速回授。`max_speed_m_s=0.30` 是**雷達估計運動變化超限時中止的門檻**，不是已實現 0.30 m/s 車速調節器。油門仍使用既有固定低速命令，不能將 PWM 命令直接換算成車速。
- ESC 中立與車身位置穩定是目前停止依據，不把它描述為已驗證的主動煞車或輪速精確歸零。

程式不會替這些條件關閉 M4 保護。若車位或場地使條件無法成立，應調整場地、起始位置或有效設定，不是把感測失效當作無障礙。

## 6. 系統分工與演算法

新停車程序使用獨立程序（multiprocessing），以兩個容量為 2 的佇列收取最新快照與回傳控制提案。車端每約 0.1 秒提供資料；影像推論及既有接收工作保持原分工。較重的線段搜尋與路徑規劃不在 UART 輸出鎖內執行。

雷達幾何使用有界隨機抽樣一致性（RANSAC）與直線擬合，根據實際牆面確認車位尺寸與入口。開始時可辨識多個車位，選距入口最近者；選定後持續追蹤同一車位，不能在行駛中自行換位。

路徑使用有界混合 A 星搜尋（Hybrid A*），包含車輛前進、倒車、最小轉彎半徑與車體碰撞限制。跟隨使用幾何路徑投影及純追蹤（Pure Pursuit）；倒車使用實際車身曲率定義，不重複翻轉舵機方向。每次新定位後再用最新回波檢查局部行駛範圍。

父程序仍由原唯一 UART 通道輸出，並核對執行期識別、模式代次、來源時間與命令範圍。移動提案的資料有效期最長 0.35 秒；重複快照或只更新一小部分回波不能假裝整個環境更新。停止提案優先於去重規則；舊模式命令、過期命令及斷線恢復都不能自行續駛。

因目前 SDK 的逐點資料沒有硬體掃描時間戳，時效以 Jetson 接收單調時間為基準；本版不宣稱硬體同步或已補償所有掃描運動畸變。

第七階段展示紀錄仍可使用，會保留模式、停車狀態、原因及完成結果。匯出指令沿用原版。

## 7. 驗證範圍

本次只改設定來源與操作方式，停車幾何、路徑、M4 保護、唯一 UART 寫入路徑及控制程序分工保持原版。本次 17 項測試全部通過，涵蓋固定設定載入、舊／壞 JSON 不影響行為、缺值禁止啟用、完整但停用時仍同步雷達座標、字典副本隔離、關閉標準輸入仍能正常執行 status、舊寫入指令拒絕，以及預覽新鮮度／待命／同次開機保護與實際射線資料的預覽輸出。4 個程式檔通過 Python 3.8 語法檢查，47 個預設參數數值與 v1 相同。

前一版的幾何與運動學模擬結果仍屬軟體驗證。你已確認實車通過的是第八階段；第九階段找位與倒車功能尚不能由這次設定改版宣稱已完成實車驗證。
