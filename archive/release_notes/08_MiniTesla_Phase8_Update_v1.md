# MiniTesla 第八階段：統一操作視窗

接續第七階段，補上原先規劃的統一操作介面。本包只有 2 個新增程式與本說明，共 3 個檔案。

## 放置檔案

| 包內檔案 | 操作 |
| --- | --- |
| `PC/pc_dashboard.py` | 放到電腦端原本 `pc_control.py` 所在資料夾 |
| `PC/pc_media.py` | 放到相同資料夾 |

請保留同層既有的 `pc_control.py`（第六階段）與 `pc_receive.py`（第四階段）。新版會載入前者的控制狀態機與後者的影像協定，所以這兩個檔案仍然需要，但不再分別執行。它們沒有修改，因此本包不重複附上。

這個資料夾中應有：`pc_dashboard.py`、`pc_media.py`、`pc_control.py`、`pc_receive.py`。

此次只更新電腦端。Jetson 沿用第七階段的開機服務，M4 沿用現有韌體。

## 啟動方式的差異

先關閉原本的電腦控制視窗、影像接收視窗及雷達接收視窗，確認它們的程序已結束。再於上述資料夾使用原本的 Python 環境執行：

```bash
python pc_dashboard.py
```

若原本環境使用 `python3`，就將指令中的 `python` 改為 `python3`。

之後電腦端只需啟動這一個程式。它會自行開啟背景接收程序，不必額外執行 `pc_media.py`，也不要同時啟動舊的控制或接收程式。

使用既有的視窗工具（Tkinter）、影像函式庫（OpenCV）與數值函式庫（NumPy），沒有新增第三方套件或驅動下載。若提示缺少套件，先確認使用的是原先能執行 `pc_receive.py` 的 Python 環境。

## 同一個視窗可以看到什麼

| 區域 | 內容 |
| --- | --- |
| 左上影像 | 車端已標示辨識結果的影像，按比例縮放至最多 640×360 |
| 左下雷達 | 原始掃描點，顯示半徑 6 公尺，逾 0.5 秒的點移除 |
| 右側操作與狀態 | 模式切換、停止、故障解除、四向距離、M4／影像狀態、人物警示、巡邏及直線倒車入庫狀態 |

右欄可以捲動，滑鼠移到右欄再使用滾輪。原有模式按鍵與車輛操作方法沿用上一版。

點擊同一視窗內的相機或雷達區域可繼續操作。切換到其他程式、縮小或關閉操作視窗，仍會要求停止待命；回到視窗後不會自動恢復行駛。

切換回視窗後，請放開操作鍵再重新按下。若模式鍵第一次沒有回應，放開再按一次：這是為了避免失去焦點時漏掉放開事件，回來後因按鍵自動連發而重新啟動巡邏或入庫。

## 影像、雷達與控制如何分工

- 主程序使用同一個視窗事件迴圈處理介面與既有控制通訊，沿用唯一的控制封包傳送路徑。
- 另開一個背景程序（multiprocessing），在其中以兩個執行緒（threading）分別接收影像與雷達。
- JPEG 解碼與縮放在背景程序完成，透過有容量上限的佇列（Queue）交給視窗；背景程序不操作視窗元件。
- 只有主視窗已接收圖片、交付可見畫面更新，且連線識別、影格識別與期限仍相符時，才允許背景程序回傳該影格的確認。單純解碼完成不算確認。
- 電腦端解碼與等待顯示共用 0.75 秒期限；車端仍保留原本從影格擷取開始計算的 1 秒有效期限。這兩個期限的起算點不同。
- 一般影像斷線會重新等待車端連線；失聯與重新連線後的模式處理仍由既有車端控制管理器負責。
- 背景接收程序非預期停止或連接埠無法開啟時，操作台會要求停止、結束接收並在終端顯示錯誤。重新啟動操作台後仍須重新選擇模式。

上述確認代表程式已完成對應的顯示處理，不是螢幕硬體或人的觀看確認。

控制狀態逾時後，四向距離與 M4 連線狀態顯示「未知」，不會把最後一筆資料繼續當成即時狀態。雷達圖只使用原始角度，0° 在圖右、90° 在圖上；目前沒有車頭方位校正，不將圖上的上方標成車頭。雷達顯示不改變現有四向測距避障與入庫判斷。

## 連線設定

既有 IP 與埠號保持相容。Jetson 的電腦目的 IP 沿用 `192.0.2.10`；此操作台在電腦本機監聽：

| 資料 | 通訊方式 | 預設埠號 |
| --- | --- | --- |
| 控制與車端狀態 | 使用者資料報協定（UDP） | 5000 |
| 雷達 | 使用者資料報協定（UDP） | 6000 |
| 影像 | 傳輸控制協定（TCP） | 7000 |

原有 5G 行動分享器（MiFi）與網路位址轉換穿透（NAT traversal）方式沿用。預設監聽 `0.0.0.0`，代表電腦的所有本機介面，不是要填在 Jetson 的目的 IP。

若先前已自訂埠號，可在新指令指定相同設定：

```bash
python pc_dashboard.py --bind 0.0.0.0 --port 5000 --lidar-port 6000 --video-port 7000
```

## 問題判讀

| 現象 | 處理 |
| --- | --- |
| 找不到 `pc_control` 或 `pc_receive` | 將前述兩個既有檔案保留在新程式同層 |
| 顯示連接埠已被占用 | 關閉舊控制／接收程序或另一份操作台，再啟動一次 |
| 有控制狀態，影像尚未就緒 | 檢查車端相機服務與既有 TCP 7000 連線；影像恢復後按原流程解除故障並重新選擇模式 |
| 雷達沒有點 | 查看車端雷達服務及 UDP 6000；沒有有效回波時不會保留舊點充數 |
| 縮小後車輛停止 | 符合本版行為；恢復視窗後檢查狀態，再重新選擇模式 |
| 人物或入庫說明沒有全部顯示 | 在右側狀態欄向下捲動 |

展示紀錄仍由 Jetson 第七階段的紀錄程序保存，匯出方法沿用上一版。

本次變更為操作介面整合，沒有增加車位搜尋、轉向對位、定位建圖或路徑規劃；直線倒車入庫的適用範圍仍以第六階段為準。

## 本版驗證範圍

55 項自動測試通過，並以真正的 Tk 視窗、背景程序及模擬 TCP／UDP 資料驗證影格確認、隱藏視窗停止、恢復後不自動啟動、舊距離失效與關閉後連接埠釋放。兩個新程式也通過 Python 3.8 語法相容性檢查。

尚未在你的 Windows 電腦或實車上驗證。測試環境的中文字型未完整呈現，因此不將測試截圖視為中文排版驗證；Windows 的字型與顯示縮放仍需於實際電腦確認。

實作參考：[Python 官方視窗事件與圖片說明](https://docs.python.org/3/library/tkinter.html)、[Python 官方多程序與佇列說明](https://docs.python.org/3/library/multiprocessing.html)。
