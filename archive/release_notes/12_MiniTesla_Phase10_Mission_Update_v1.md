# MiniTesla 第十階段：巡邏找位、通知確認、自動入庫

本版將你指定的流程接成一個任務：

**巡邏 → 發現車位 → 停止並確認車位穩定 → 通知與倒數 → 你同意 → 轉向對位、倒車入庫。**

車端提供最多 15 秒做決定。按 Y 同意才入庫；按 N 略過後繼續找位；沒有回覆就停止待命。找位與等待合計最多 120 秒，此總期限優先，末段找到車位時剩餘決定時間可能少於 15 秒。介面顯示車端實際剩餘時間。

## 更新方式：只合併本次修改檔

接續已合併的第九階段 v1、固定參數 v2、參數 v3 使用。本包為增量更新，沒有附上未修改檔案，也不能單獨取代整個專案資料夾。

先關閉電腦端操作視窗，在 Jetson 原本環境執行：

```bash
cd "$HOME/Desktop/jetson orin nano"
python3 minitesla_service.py stop
```

將本包 `Jetson` **裡面的內容**合併到上述目錄、覆蓋同名檔案；本包 `PC` 裡面的兩個檔案覆蓋到電腦端原資料夾。保留其他原檔。

```bash
python3 minitesla_service.py restart
```

電腦端照原方式執行 `python pc_dashboard.py`。兩端均須重新啟動以載入新版。若原本採手動啟動車端，也照原方式重新執行，不同時再開第二個車端主程式。

本次不用安裝新套件、下載原廠驅動或重新燒錄 M4；沿用既有 NumPy、雷達 SDK、`best.pt`、服務及通訊設定。電腦位址仍為 `192.0.2.10`。

## 新增操作

| 操作 | 行為 |
| --- | --- |
| 空白鍵後按 **G** | 從待命開始「巡邏找位」任務；開始前會先等待有效雷達偵測回報 |
| 看見通知後按 **Y** | 同意停入本次通知的車位，重新確認定位並規劃路徑，之後轉向與倒入 |
| 看見通知後按 **N** | 略過本次通知，經中立交接後繼續巡邏找位 |
| 不回覆 | 倒數結束後停止待命，不自行入庫，也不自行恢復巡邏 |
| 空白鍵 | 結束當前任務、停止待命 |
| **M** | 結束自主任務並依原規則交接到手動；重新按 WASD 才行駛 |

通知固定顯示在統一操作台上方，包含倒數、Y 與 N 按鈕。每次新通知會嘗試響一次系統提示音，是否有聲音取決於電腦的音效設定；畫面通知仍是主要依據。不會跳出另外的對話框搶走操作視窗焦點。

**N 的再次通知規則：至少經過 10 秒，且雷達連續 1 秒看不到任何可辨識車位，才重新允許通知。** 這是防止車輛尚未離開時反覆詢問；若連續一排車位始終可見，通知也會暫時被抑制。需要重新開始時，按空白鍵回待命再按 G。

原有 **P** 仍是普通反應式巡邏；**K** 仍是從目前位置辨識可見車位並直接入庫，不經本次詢問流程。要展示「找位後讓你決定」請按 G。

失焦、縮小視窗、連線或影像監督中斷沿用既有停止規則。恢復連線不會接續舊通知或自主行駛；有故障時沿用 R，再回待命選擇模式。

## 這次如何串接

1. `search` 模式沿用四向 ToF 反應式巡邏，雷達車位偵測在原停車子程序內運行。
2. 找到候選車位就切到 `offer`，主控制器立刻改送中立命令。
3. 持續追蹤同一車位，確認 M4 回報中立，並累積至少四筆新掃描及至少 0.5 秒位置穩定後，才開放 Y／N 與倒數。
4. Y 必須對應目前會話、模式代次和通知編號。車端重新檢查期限、感測與最新車位資料，通過後將同一車位交給原停車控制器。
5. 入庫重新取得新掃描及規劃路徑；無可行路徑就停止，不會換選另一個未經同意的車位。完成後回待命。

較重的雷達幾何與規劃仍在原獨立程序（multiprocessing）內；容量為 2 的佇列傳送最新資料。未新增 UART 寫入者；子程序不能直接控制 M4。主程序的控制鎖、模式代次與逾時檢查決定最終輸出。重複資料不能延長倒數或偽裝成新感測資料。

M4 既有 ToF 保護沿用。新增找位及等待模式也要求四向測距有效且大於 450 毫米；雷達來源失效、等待期間失去車位或車身移動、M4 重啟等會中止任務。中立命令與定位穩定是目前停止依據，不將其稱為已量得零車速或新增 ESC 主動煞車。

## 已寫入的設定

| 項目 | 固定值 |
| --- | --- |
| 通知決定時間 | 最多 15 秒，受任務總期限限制 |
| 找位與等待總期限 | 120 秒；按 N 不重新計時 |
| 車位停穩確認期限 | 5 秒 |
| 略過後通知抑制 | 至少 10 秒，且連續 1 秒無可辨識車位 |
| 找位偵測持續回報期限 | 0.5 秒；新回報仍須符合原 0.35 秒來源有效期 |
| 同意後入庫期限 | 沿用 90 秒 |
| 左／右轉彎半徑 | 各 48 公分 |
| 車尾到後軸中心 | 14 公分 |
| 雷達 | 原始 0° 朝前、角度順時針、橫向置中 |
| 展示車位內寬／內深 | 沿用選定的 180／130 公分 |

數值都已寫入 `vehicle_config.py`，啟動時不用輸入。車長 47.4、車寬 32.8、軸距 27.5、雷達距車尾 30 公分沿用原值；舊 `parking_config.json` 仍不參與載入。

找位辨識依雷達可見的三面實體擋板，不辨識僅貼在地面的車位線。展示車位與外部轉向空間沿用第九階段 v3 的配置。巡邏路線由現有 ToF 避障決定，沒有建圖、定位建圖（SLAM）、預先地圖或全室覆蓋保證。找到幾何候選也不代表一定能規劃出入庫路徑，路徑確認發生在 Y 之後。

## 驗證範圍

- 277 項離線測試通過：30 項新控制測試、28 項偵測與目標鎖定測試、16 項獨立控制審查、64 項操作台與既有焦點／影格確認測試、5 項新增紀錄與狀態測試，另有 89 項舊控制與並行、22 項舊停車介面、23 項紀錄回歸。
- 實際建立 `spawn` 子程序，透過容量為 2 的佇列走過發現車位、停穩、確認後重新追蹤，以及正常退出。
- 以實際交付的車輛參數、雷達射線、車體碰撞與運動學模型完成兩個全流程：開始即看到車位，以及先巡行約 73.35 公分再看到車位。兩者均經通知、同意、轉向、換向、倒車、停妥回待命。
- 巡行測例使用固定局部遮擋，沒有直接注入「找到車位」或把車身座標跳到目標。四向理想射線全程約 461～1970 毫米；每 5 毫秒檢查車體碰撞與有效距離，沒有碰撞。末位誤差約 2.56 公分、角度差約 6.00°，在原 8 公分／6° 門檻內。
- 不回覆的完整幾何測例保持中立，15 秒截止後回待命；另有截止時刻、等待控制鎖後過期、舊通知、雷達重播、M4 重啟和影像中斷等負向測試。
- 狀態封包低於原 4096 位元組限制；全部交付程式通過 Python 3.8 語法檢查。

上述為本機軟體、程序與理想模擬驗證，**不是第十階段實車測試結果**。網路、影像與 M4 遙測使用模擬輸入；運動模型未涵蓋打滑、光學反射材質、舵機非線性與實車煞停延遲。你先前確認實車成功的版本不因此被改寫為已驗證本次新增任務。
