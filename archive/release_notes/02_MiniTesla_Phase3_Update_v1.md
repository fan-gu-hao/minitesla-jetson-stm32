# MiniTesla 第三階段：模式切換與控制權管理

本包是套用在 `MiniTesla_Phase1_2_Replace_v1.zip` 之上的增量更新。共 7 個檔案：6 個新增／修改的程式及本說明。每個程式都是完整檔案，可直接新增或覆蓋，不必手動貼程式片段。

本階段完成待命、手動接管、停止、故障待命與解除故障，以及電腦端操作視窗和狀態回傳。開機先待命；接管後先送中立，再接受新油門。重連不會自動恢復行駛。人物警示、自動避障決策、巡邏、停車與開機自動啟動仍待後續實作；介面中的巡邏／停車按鈕目前停用。

## 1. 檔案對應與替換

先結束正在執行的 Jetson 主程式及舊電腦端控制程式，保留上一版作為備份。

| 壓縮包內路徑 | 放置位置／用途 |
| --- | --- |
| `Jetson/minitesla.py` | 覆蓋車端程式資料夾的同名主程式 |
| `Jetson/minitesla_sensors/core.py` | 覆蓋同名檔，提供輕量控制健康狀態 |
| `Jetson/minitesla_sensors/io.py` | 覆蓋同名檔，整合新版控制通訊與 UART 輸出 |
| `Jetson/minitesla_sensors/control.py` | 新增至原 `minitesla_sensors` 資料夾，管理模式與控制權 |
| `Jetson/sensor_status.py` | 覆蓋同名監看程式 |
| `PC/pc_control.py` | 放在電腦端，以後用它取代舊 `sever(1).py` 控制程式 |
| `README_使用說明.md` | 本次使用說明 |

將 `Jetson` 裡面的內容「合併並覆蓋」到原程式資料夾，**不要先刪除整個舊資料夾**。保留原 `sensor_config.json`、`minitesla_sensors/__init__.py`、`best.pt` 及其他原有依賴。此次控制參數有內建預設值，原設定檔可以直接使用，也不會覆蓋你已調好的 IP 或感測器設定。

若上一版 M4 已燒錄，這次不需重新燒錄、不更動接線，也不用下載新驅動。M4 UART 協定、四向 ToF 與底層保護沿用上一版。若尚未安裝第一、二階段，請先完成上一包的更新，本包不能單獨取代全部專案。

電腦端控制協定已更新，**不可繼續使用舊 `sever(1).py` 控制新版 Jetson，也不可同時開兩支控制程式**。原影像與雷達接收程式 `from_jetson_orin_nano(1).py` 繼續沿用。

## 2. 啟動順序

### 電腦端

在有 `pc_control.py` 的資料夾開啟終端機：

```powershell
py pc_control.py
```

若你的環境原本使用 `python` 指令，改用 `python pc_control.py`。本程式使用 Python 標準函式庫與 Tkinter，不需安裝 `keyboard` 等新套件；Python 環境須包含 Tcl/Tk（Windows 官方安裝程式提供此項）。介面開啟後會先顯示等待車端連線。

另外啟動原影像／雷達接收程式：

```powershell
py "from_jetson_orin_nano(1).py"
```

沿用目前已通的 MiFi、5G 與 NAT 穿透路徑；控制仍使用 UDP 5000，影像／雷達使用原連接埠。若 Windows 因新程式出現防火牆提示，允許它在你原本使用的網路接收通訊。

### Jetson 雷達

在原雷達 SDK 目錄啟動既有讀取程式：

```bash
cd ~/Desktop/rplidar_sdk-master/output/Linux/Release
./ultra_simple --channel --serial /dev/ttyUSB0 460800
```

### Jetson 主程式

另開終端機，進入原車端程式資料夾，啟用你原先執行模型的 Python 環境，再執行：

```bash
python3 minitesla.py
```

主程式保留原 `sensor_config.json` 的 `network.pc_host`。若該值為 `null`，預設為 `192.168.225.46`。若你目前走原先的跨網路位址，改用下面這一條，不要同時啟動兩份主程式：

```bash
python3 minitesla.py --pc-host 120.126.10.41
```

位址以你目前已通的那一個為準。沒有 Jetson 本地桌面時加 `--no-display`；模型不在程式旁時加 `--model /實際路徑/best.pt`。不要另開舊 UART 橋接程式或 `lidar_receive.py`，避免占用相同裝置／連接埠。

### 監看

第三個 Jetson 終端機，進入同一程式資料夾：

```bash
python3 sensor_status.py
```

現在會同時顯示上層模式、控制原因、手動是否就緒、模式版本、命令年齡及原有感測狀態。要查看完整快照一次，使用 `python3 sensor_status.py --once --json`。監看程式只讀快照，不會再次開啟 UART。

## 3. 實際操作

將鍵盤焦點放在新版控制視窗；開機或剛連線時為「待命」。

| 按鍵／按鈕 | 行為 |
| --- | --- |
| `M`／手動接管 | 健康條件成立時請求手動控制；先等待「手動就緒」 |
| `W`／`S` | 增加／降低 ESC 命令，沿用原前進與倒車控制方式 |
| `A`／`D` | 左／右轉向 |
| 放開方向鍵 | 輸出逐步回中立，沿用鍵盤控制手感 |
| 空白鍵／停止待命 | 立即請求中立並回待命；若已故障，仍保留故障狀態 |
| `R`／解除故障 | 健康條件恢復後，故障→待命，不直接起步 |
| 巡邏／停車 | 本階段尚未開放 |

正常操作順序：**連線 → M → 等待手動就緒 → WASD → 空白鍵停止**。解除故障後要再按一次 `M`，等手動就緒後才可控制。

切換模式時會清空已按住的方向鍵，因此不要一直壓著 `W` 等待接管；待就緒後放開並重新按下。控制視窗失去鍵盤焦點會請求停止，所以點到其他視窗後，要回到控制視窗重新接管。關閉控制視窗也會嘗試送出停止；若封包無法送達，車端由控制逾時機制接手。

## 4. 狀態與故障處理

- **待命**：持續送出 ESC／舵機中立值 152／152，不會收到方向鍵就直接起步。
- **手動**：只有明確接管後的新命令可驅動。切換至少維持 100 毫秒中立，且須收到新模式版本的中立命令才會就緒。
- **故障待命**：手動命令逾時 300 毫秒、M4 回報失效、任一 ToF 無效／過期或 M4 保護鎖定時，車端控制迴圈轉中立並鎖定。這是軟體判斷門檻，不是作業系統排程與實體煞停時間的保證。

M4 的原底層保護始終優先。啟動時可能短暫顯示感測尚未就緒；上一版的解除條件仍是四向距離至少 400 毫米持續 500 毫秒並收到中立命令。障礙物未離開、ToF 無效或 UART 未恢復時，按 `M`／`R` 不會強制繞過保護。狀態列會顯示拒絕原因。

若顯示故障，先依狀態原因排除障礙或恢復原有連線；健康狀態恢復後按 `R` 回待命，再按 `M`。若 Jetson 終端機已顯示 UART 開啟／寫入失敗，恢復裝置後須重新啟動主程式。網路恢復或電腦端重開不會自動沿用斷線前油門。若車端回報停更超過 500 毫秒，電腦端停止送命令並清空按鍵，重新收到狀態後先請求停止。

本階段以 UDP 控制心跳管理手動失聯。影像 TCP 連線狀態尚未整合成模式切換條件，也尚未實作失聯後的自主巡邏；不要把本階段描述成已完成全部自主行駛功能。

已通過 40 項模式、電腦端狀態與本機 UDP／模擬 UART 測試，涵蓋切換後中立、停止後舊命令、重連、ToF 過期、控制逾時、封包格式、UART 錯誤與命令校驗。另檢查以第一、二階段設定檔合併更新後可載入，以及 Python 3.8 語法相容性。
