# MiniTesla 第五階段：四向測距反應式巡邏與人物警示

本包接續 `MiniTesla_Phase4_ConcurrencyFix_v1.zip`。只包含 4 個修改後的完整程式、1 個新增程式及本說明，共 6 個檔案。啟動指令、IP、連接埠與接線全部沿用上一版，下面只列本次差異。

## 一、本次替換

先停止 Jetson 主程式及電腦端控制台，再合併覆蓋同名檔案。

| 包內檔案 | 放置位置與操作 |
| --- | --- |
| `Jetson/minitesla_sensors/core.py` | 車端原 `minitesla_sensors` 內覆蓋 |
| `Jetson/minitesla_sensors/control.py` | 車端原 `minitesla_sensors` 內覆蓋 |
| `Jetson/minitesla_sensors/autonomy.py` | 車端原 `minitesla_sensors` 內新增 |
| `Jetson/sensor_status.py` | 車端專案根目錄覆蓋 |
| `PC/pc_control.py` | 電腦端原控制程式覆蓋 |
| `README_使用說明.md` | 本說明 |

不要刪除原資料夾。更新後 `minitesla_sensors` 應有 `__init__.py`、`core.py`、`io.py`、`control.py`、`runtime.py`、`autonomy.py` 六個程式檔。

原 `minitesla.py`、`io.py`、`runtime.py`、`__init__.py`、`sensor_config.json`、`best.pt`、`pc_receive.py` 與雷達 SDK 都保留，沒有重複附上。M4 不需重燒；本次不增加驅動、模型或第三方套件。

兩端更新後沿用原指令啟動。電腦端控制台會顯示「第 5 階段」，新增可使用的「P 反應式巡邏」按鈕。目標 IP 仍沿用 `192.0.2.10`。

## 二、操作差異

| 操作／狀況 | 本版行為 |
| --- | --- |
| 按 `P` 或點「反應式巡邏」 | 等四向測距、M4、影像接收確認及辨識資料就緒後，經中立交接開始巡邏 |
| 巡邏期間按 `M` | 切成手動並先回中立；等手動就緒後重新按方向鍵 |
| 手動期間按 `P` | 清除手動按鍵與舊油門，經中立交接開始巡邏 |
| 巡邏期間按方向鍵 | `W/S/A/D` 不直接控制車輛；要人工駕駛請先按 `M` |
| 空白鍵或控制台失去焦點 | 沿用原行為：要求停止待命，因此巡邏時也須保持控制視窗焦點 |
| 路徑受阻或繞行逾時 | 回待命，距離恢復後不自行起步；清出空間或手動調整車位後，再按 `P` |
| 影像、控制心跳、辨識資料或測距異常 | 進入故障待命；原因排除後按 `R`，再選 `M` 或 `P` |
| M4 串口故障使車端主程式結束 | 沿用上一版：排除原因後重新啟動車端主程式 |

巡邏是「有人監督的自主決策」：電腦端仍持續送出中立心跳，由 Jetson 產生行車命令。關閉控制台、影像接收器或網路中斷，都不會讓車子繼續無人監督巡邏。重連也不會自動恢復。

## 三、巡邏如何決定方向

本版用前、後、左、右四顆飛行時間測距器（ToF）的有效距離做反應式決策。預設規則如下，距離均為感測器量到的距離：

| 條件 | 行為 |
| --- | --- |
| 前方至少 950 毫米，其他方向通過下列條件 | 向前巡行 |
| 前方小於 950 毫米、仍大於 500 毫米 | 選擇左右距離較大且至少 650 毫米的一側轉向；兩側相同時選左 |
| 已經轉向 | 保持所選方向，不因左右數值小幅變動反覆換邊 |
| 轉向後前方至少 1100 毫米，連續保持 0.5 秒 | 結束轉向，恢復直行 |
| 前方小於或等於 500 毫米 | 停止並退出巡邏 |
| 後方、左方或右方任一方向小於或等於 450 毫米 | 停止並退出巡邏 |
| 左右兩側都小於 650 毫米 | 停止，不嘗試穿越狹窄通道 |
| 已選轉向側變成小於 650 毫米 | 停止，不立即換向繼續嘗試 |
| 單次轉向達 2 秒仍未完成 | 停止並退出巡邏 |

停止與感測異常檢查優先於行駛規則。巡邏前進命令預設為電子變速器（ESC）值 154，中立值 152；左右轉向分別為 128、176。這些是命令值，並非實測速度或轉彎角度。

這版只會前進與轉向，不自動倒車、不原地轉向、不建立地圖，也不記錄固定巡邏路線。四顆測距器無法涵蓋整台車的掃掠範圍，距離門檻不是保證制動距離；M4 既有保護照常保留，底層的停止輸出仍為 ESC 中立值。

現有設定未提供雷達相對車頭的安裝朝向，因此雷達繼續讀取、顯示及回傳，本階段不使用它決定轉彎方向。沒有替你猜測雷達角度，也沒有把未量到的區域當成可通行空間。

## 四、人物警示

控制台及 `sensor_status.py` 新增：目前辨識人物數量、人物警示事件累計、資料是否有效。

- 人物警示在手動、待命及巡邏時都會更新；不是只有巡邏才辨識。
- 使用現有 `best.pt` 輸出的類別名稱判斷人物，不把第 0 類固定認定為人。預設接受 `person`、`persons`、`person(s)`、`people`、`human`、`人`、`人物`、`行人`，不區分英文大小寫，信心值須至少 0.5。
- 模型本身須具有對應人物辨識能力。本包沒有重新訓練模型，也沒有新增人物類別；漏檢不會被解讀成環境中一定沒有人。
- 連續辨識到人物只算一段警示事件。連續有效且未辨識到人物的影格滿 1 秒後，下一次出現才新增事件；不是每張影格加一，也不是不同人物身分的累計。
- 警示數在本次主程式執行期間累計，重新啟動歸零，沒有新增永久事件紀錄檔。
- 相機資料過期或錯誤時顯示「未知」，不顯示成目前沒有人。
- 人物與其他障礙物使用相同的測距避障規則，不因辨識到人物就額外觸發特殊煞車；也沒有把人物影像框和雷達點做幾何配對，人物距離仍為未知。

警示透過原控制狀態回傳，沒有新增網路連接埠或變更 MiFi／5G／NAT 穿透配置。

## 五、可選設定

不修改 `sensor_config.json` 也能使用預設值。若日後要調整，可將以下兩個區段合併至原設定檔的最外層，保留原本其他區段；不要用這段取代整份設定檔。

```json
{
  "autonomy": {
    "forward_esc": 154,
    "left_servo": 128,
    "right_servo": 176,
    "stop_front_mm": 500,
    "side_stop_mm": 450,
    "turn_start_mm": 950,
    "clear_front_mm": 1100,
    "side_clear_mm": 650,
    "max_turn_s": 2.0,
    "stable_clear_s": 0.5
  },
  "perception": {
    "person_class_names": ["person", "persons", "person(s)", "people", "human", "人", "人物", "行人"],
    "min_confidence": 0.5,
    "clear_hold_s": 1.0
  }
}
```

`side_stop_mm` 同時套用後、左、右。前進命令限 153～156；前、側停止門檻不得低於 400 毫米；前方門檻須符合「停止 < 開始轉向 < 恢復直行」。這些限制會在啟動時檢查。改完設定須重啟主程式。

## 六、多工與驗證

本次沒有新增直接寫入馬達的執行緒。巡邏規劃器是由原唯一串口輸出流程同步呼叫的短運算，仍在控制鎖內完成模式判斷及送出。人物摘要在接收到新影格時計算一次，控制迴圈只讀取精簡結果，不反覆複製影像輪廓。

切換到巡邏後，必須收到新模式代次的中立心跳，舊模式封包或非中立封包不能維持巡邏。原中立交接、控制心跳逾時、影像確認、串口排他及單一實例保護均保留。

共 152 項軟體測試通過，涵蓋原 87 項回歸測試，以及方向門檻、轉向保持與逾時、模式交接、舊封包拒絕、人物事件去重、過期未知及電腦端操作。另以真實本機 UDP 連線和模擬 UART 驗證「電腦啟動巡邏→回傳人物警示→相機失效後中立→資料恢復不自啟」的完整流程。

已確認 Python 3.8 語法與上一版保留檔案合併後的載入。未連接你的實車，未執行 Jetson GPU 推論或 Windows 圖形介面；以上不是實車避障成功率、速度或煞車距離的量測結果。

後續尚待完成智慧停車／倒車入庫、開機自動啟動與展示紀錄。
