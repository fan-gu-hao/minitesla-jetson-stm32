# MiniTesla 第九階段：實體車位搜尋、轉向對位與倒車入庫

接續你已實車測試通過的第八階段。此次新增功能是：**車子原地辨識目前雷達可見的三面實體車位，選擇車位、規劃前進／倒車路徑、轉向對位，再倒車停入。** 不需要人工先把車身對正，但必須先位於能觀察車位、且有可行進退空間的位置。

此版不包含「看不到車位時自行巡航探索整個房間」，也不辨識僅畫在地面的車位線。原有巡邏模式仍獨立使用。

## 1. 本包只有新增與修改檔案

| 檔案 | 操作／作用 |
| --- | --- |
| `Jetson/minitesla.py` | 覆蓋；管理新的停車計算程序及設定載入 |
| `Jetson/minitesla_sensors/control.py` | 覆蓋；在原唯一控制輸出路徑驗證停車命令 |
| `Jetson/minitesla_sensors/parking_config.py` | 新增；設定與範圍檢查 |
| `Jetson/minitesla_sensors/parking_geometry.py` | 新增；辨識實體車位及估計相對位置 |
| `Jetson/minitesla_sensors/parking_path.py` | 新增；進退路徑規劃、跟隨及碰撞檢查 |
| `Jetson/minitesla_sensors/parking_auto.py` | 新增；串接尋位、對位、換向、倒車與到位流程 |
| `Jetson/parking_config.json` | 新增；本車專用停車設定 |

| `Jetson/sensor_status.py` | 覆蓋；顯示新增停車狀態 |
| `PC/pc_control.py` | 覆蓋；停車狀態與命令說明 |

共 **12 個檔案**。合併覆蓋到原資料夾，不要刪掉整個原資料夾。既有 `pc_media.py`、`pc_receive.py`、`minitesla_sensors` 其他模組、服務工具、紀錄工具及 `best.pt` 都仍需保留。本包沒有重複附上未修改的檔案。

沿用原有 NumPy 與其他環境，沒有新增套件、驅動或模型下載；不用修改 RPLIDAR SDK，不用重新燒錄 M4。電腦目的位址仍用 `120.126.10.41`，三個既有通訊埠及行動分享器連線方式相同。

## 2. 第一次更新與設定

先關閉電腦端操作視窗。Jetson 在原本環境執行：

```bash
cd "$HOME/Desktop/jetson orin nano"
python3 minitesla_service.py stop
```

合併本包的 `Jetson` 檔案到此資料夾；`PC` 檔案則合併到電腦端原資料夾。

**新增設定檔預設未啟用自動停車。** 手動與巡邏仍可使用，但 K 會顯示尚未完成停車設定。這不是缺少驅動，而是原有資料沒有完整記錄雷達朝向、中心線偏移與轉向幾何；不能把未確認值直接用來決定車身路徑。

在 Jetson 開啟互動設定：

```bash
python3 parking_setup.py configure
```

依提示填寫下列資料。直接按 Enter 會保留現有值；尚無資料的欄位會保持未設定。

| 設定 | 定義與來源 |
| --- | --- |
| 掃描方向 | 原始雷達角度遞增時是順時針或逆時針 |
| `lidar_yaw_deg` | 雷達原始 0° 對應的車體方向；向前為 0°，向右為 +90°，向後為 ±180° |
| `lidar_y_from_center_m` | 雷達旋轉中心相對**車身中心線**的橫向距離，單位公尺；向右為正、向左為負 |
| `rear_overhang_m` | 車尾至後軸中心的距離，單位公尺，不是整車軸距 |
| `left_turn_radius_m` | 使用 `steering_left_pwm` 時，後軸中心的左轉半徑，單位公尺 |
| `right_turn_radius_m` | 使用 `steering_right_pwm` 時，後軸中心的右轉半徑，單位公尺 |
| 車位內寬與內深 | 此次實體車位的尺寸，預設寬 1.6 公尺、深 1.8 公尺 |

原資料有雷達 `y=181 mm`，但沒有明確說明橫向原點是否為中心線，因此不直接把它當成右偏 181 mm。若原本是從左側車緣量起，在原點確實如此且車寬為 328 mm 的前提下，中心線偏移才是 `181−164=17 mm`；若原本就是中心線座標，就不應扣除。請依實際原點填寫，不能任選一個數字。

轉彎半徑須對應實際使用的轉向命令；預設左 128、右 176，中立 152。這些 PWM 命令值不是角度，不能把 `128` 當成 128°。左右半徑可不同；規劃會採較大的半徑作為共同限制，控制再依左右校正值換算命令。程式使用兩端校正點間的近似曲率插值，並由雷達位置回授修正。

若你已有「正前方物體在原始雷達圖上的角度」，可用下列命令查看完整非互動設定選項，讓工具計算朝向偏角：

```bash
python3 parking_setup.py set --help
```

`--front-angle` 接受該物體的原始角度；與 `--clockwise` 或 `--counterclockwise` 搭配。其他 `--…-mm` 參數輸入毫米，工具會換算成公尺。單獨變更掃描方向會清除舊朝向；變更任一幾何設定後都會停用自動停車，需要重新啟用。

核對設定：

```bash
python3 parking_setup.py status
```

## 3. 先看不會移動車輛的預覽

擺放三面固定擋板形成 U 形車位，入口朝走道。擋板必須高於雷達實際掃描平面；依目前配置約離地 315 毫米，不可只在地上貼膠帶或放低於掃描面的物體。

入口、兩側牆及後牆需要能被雷達觀察。開始時可以有車身角度，但遮住大部分車位、背後只有未知空間、或看不到足夠牆面時，程式會拒絕規劃。車位外也需要供車頭和車尾轉動的空間。

若要先搭一組展示場景，下列是已通過理想幾何模擬的配置，可作為起點；使用時將車位寬深設定改為相同尺寸，不沿用預設寬深：

| 項目 | 模擬配置 |
| --- | --- |
| 車位內寬／內深 | 1.8／1.3 公尺，兩側與後方有實體擋板 |
| 周圍封閉空間 | 長 3.4 公尺、寬 2.8 公尺；以車位後牆中央為原點，X 為 −0.5～2.9、Y 為 −1.4～1.4 公尺 |
| 起始後軸中心 | 約 X=1.925、Y=0 公尺，車頭相對入口外向轉 90° |
| 模擬轉彎半徑 | 左右均 0.65 公尺，**這是模擬條件，不是你的實車校正值** |
| 到位目標 | 後軸中心 X=0.7、Y=0、車頭朝入口外；模擬後懸長 0.1 公尺 |

上述場景的六種相近起姿都完成倒入，四向測距在每 5 毫秒模擬子步均介於約 651～1913 毫米。此結果使用理想牆面回波與車輛運動模型，不代表任意安裝、材質、地面摩擦或轉彎半徑都會得到相同結果。

先啟動車端及既有電腦端視窗：

```bash
python3 minitesla_service.py start
```

電腦端沿用：

```bash
python pc_dashboard.py
```

在操作台按空白鍵，確認車端處於待命。Jetson 執行：

```bash
python3 parking_setup.py preview
```

會在 Jetson 專案資料夾產生 `parking_preview.svg`。以瀏覽器開啟，或複製到電腦觀看：灰點是實際回波、青色路徑是前進、紫色是倒車、橘框是目前車體。

這個工具只讀取目前感測快照，**不開啟 UART、不傳送控制命令、不啟用停車**。快照過期、車端不在待命或設定不完整時會拒絕產生預覽。即使顯示可行路徑，正式按 K 時也會重新讀取感測資料並重新規劃，不沿用預覽檔。

若你改過快照路徑，可用：

```bash
python3 parking_setup.py preview --help
```

## 4. 啟用與正式操作

確認設定完整、預覽中的車位與車身方向正確後：

```bash
python3 parking_setup.py enable
python3 minitesla_service.py restart
```

不需要重新安裝服務。電腦端仍只有一個 `pc_dashboard.py`，操作差異是：

1. 先按空白鍵回待命。
2. 按 **K：自動找位入庫**。
3. 觀察狀態依序進入尋位、位置穩定確認、路徑規劃、前進調整／倒車及中立換向、停妥確認。
4. 成功後回待命，顯示入庫完成。

實際進退次序由路徑決定，可能需要先小幅倒退、再前進轉向、最後倒入；不是每次都固定前進一次再倒車一次。最後到位的路段必須是倒車。

右欄顯示目前／最後位置、目標位置、角度和目前路段剩餘距離。座標原點是車位後牆中央，X 朝入口外方、Y 向左；它與原感測檔的「車尾原點、Y 向右」不同，程式會做明確轉換。

空白鍵、手動接管、失去操作視窗焦點、縮小視窗與斷線處理都沿用既有規則。中止後不會自動重試或繼續行駛，需要回到待命再按 K。自行巡邏與停車仍為不同模式，不會在巡邏中默默切換成停車。

要暫時停用新增停車功能：

```bash
python3 parking_setup.py disable
python3 minitesla_service.py restart
```

停用後 K 不可用，手動與巡邏照常。若停車設定檔不存在，程式會保留第六階段直線倒車相容行為，操作台會明示「舊版直線入庫」；正常使用本包時請保留新的設定檔。

## 5. 會停止的情況與場地限制

- 保留現有 M4 保護；Jetson 在停車模式另要求四向 ToF 都有效且大於 450 毫米。不能把無效測距當成空曠。
- VL53L0X 的距離能力會限制場地。周圍太空曠、某一方向沒有有效反射面，也可能無法入庫；不能因雷達能看到更遠，就忽略該方向 ToF 失效。
- 雷達需要持續看到足夠不同方向的牆面。遮住後牆、只有兩面平行牆、位置突然跳變或出現多個無法區分的追蹤解，都會停止。
- 不把缺少回波的地方當作可行駛空間；障礙後方的遮蔽區也不能直接穿越。
- 轉向時檢查的是整個車體及其掃過區域，不只有車身中心點。
- 路徑偏差過大、沒有進展、定位變化超出限制、規劃或整體任務逾時，都會回中立並中止。
- 規劃完成後重新取得新掃描，才允許開始移動；計算前的舊掃描不能包裝成新命令。
- 目前沒有輪速回授。`max_speed_m_s=0.30` 是**雷達估計運動變化超限時中止的門檻**，不是已實現 0.30 m/s 車速調節器。油門仍使用既有固定低速命令，不能將 PWM 命令直接換算成車速。
- ESC 中立與車身位置穩定是目前停止依據，不把它描述為已驗證的主動煞車或輪速精確歸零。

程式不會替這些條件關閉 M4 保護。若車位或場地使條件無法成立，應調整場地、起始位置或有效設定，不是把感測失效當作無障礙。

## 6. 系統分工與演算法

新停車程序使用獨立程序（multiprocessing），以兩個容量為 2 的佇列收取最新快照與回傳控制提案。車端每約 0.1 秒提供資料；影像推論及既有接收工作保持原分工。較重的線段搜尋與路徑規劃不在 UART 輸出鎖內執行。

雷達幾何使用有界隨機抽樣一致性（RANSAC）與直線擬合，根據實際牆面確認車位尺寸與入口。開始時可辨識多個車位，選距入口最近者；選定後持續追蹤同一車位，不能在行駛中自行換位。

路徑使用有界混合 A 星搜尋（Hybrid A*），包含車輛前進、倒車、最小轉彎半徑與車體碰撞限制。跟隨使用幾何路徑投影及純追蹤（Pure Pursuit）；倒車使用實際車身曲率定義，不重複翻轉舵機方向。每次新定位後再用最新回波檢查局部行駛範圍。

父程序仍由原唯一 UART 通道輸出，並核對執行期識別、模式代次、來源時間與命令範圍。移動提案的資料有效期最長 0.35 秒；重複快照或只更新一小部分回波不能假裝整個環境更新。停止提案優先於去重規則；舊模式命令、過期命令及斷線恢復都不能自行續駛。

因目前 SDK 的逐點資料沒有硬體掃描時間戳，時效以 Jetson 接收單調時間為基準；本版不宣稱硬體同步或已補償所有掃描運動畸變。

第七階段展示紀錄仍可使用，會保留模式、停車狀態、原因及完成結果。匯出指令沿用原版。

## 7. 驗證與完成範圍

135 項自動測試全部通過；另以真正建立的獨立停車程序及程序間佇列，驗證尋位、規劃、取得新鮮移動提案與正常關閉。10 個 Python 程式通過 Python 3.8 語法相容性檢查。

本版已完成程式整合、幾何與路徑測試、控制權及過期資料測試、設定工具測試，以及真正的雷達射線／車輛運動學模擬。完整模擬涵蓋車身起初與車位垂直，再轉向、換向與倒入；不是在測試中直接把車身位置改成正確答案。

模擬仍不是實車驗證。測試分為兩類：較大房間的案例以理想 ToF 遙測注入，隔離驗證雷達定位與控制流程；第 3 節的緊湊場景則使用真正射線求交，且每個物理子步都要求四向距離大於 450、至多 2000 毫米，沒有假造超範圍有效性。另有無效測距負向案例，確認不能開始行駛。相機、網路及 M4 回報以測試資料提供，未模擬反射率、環境光、輪胎打滑或真實煞停延遲。

你先前確認通過的是第八階段版本，第九階段新增的幾何、路徑與轉向控制仍需套用實際安裝參數後確認。

新程式使用 Python 3.8 相容語法；沒有改用其他模型推論引擎，也沒有新增車位辨識模型。此版不把固定形式車位示範描述為任意場地自動停車、地面車位線辨識或全室自主尋位。
