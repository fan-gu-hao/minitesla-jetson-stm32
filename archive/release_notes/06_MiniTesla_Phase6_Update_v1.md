# MiniTesla 第六階段：已對正車位的直線倒車入庫

接續第五階段更新包。這次只包含 4 個修改後的完整程式、1 個新增程式及本說明，共 6 個檔案。啟動指令、IP、接線與既有模式操作沿用上一版，下列僅列本次差異。

## 一、替換檔案

先停止車端主程式及電腦控制台，再合併覆蓋：

| 包內檔案 | 操作 |
| --- | --- |
| `Jetson/minitesla_sensors/core.py` | 覆蓋車端同名檔 |
| `Jetson/minitesla_sensors/control.py` | 覆蓋車端同名檔 |
| `Jetson/minitesla_sensors/parking.py` | 新增至車端 `minitesla_sensors` |
| `Jetson/sensor_status.py` | 覆蓋車端監看程式 |
| `PC/pc_control.py` | 覆蓋電腦端控制台 |
| `README_使用說明.md` | 本說明 |

其餘原檔保留，不要刪掉整個資料夾。`minitesla_sensors` 現在應有 `__init__.py`、`core.py`、`io.py`、`control.py`、`runtime.py`、`autonomy.py`、`parking.py` 七個程式檔。

主程式 `minitesla.py`、第五階段巡邏程式 `autonomy.py`、影像接收器 `pc_receive.py`、原設定檔與模型皆未修改，所以不重複附上。本次不增加第三方套件、驅動或模型，M4 不需重新燒錄。

兩端使用原指令重新啟動；控制台會顯示「第 6 階段」，新增可使用的 `K` 直線倒車入庫按鈕。目標 IP 仍沿用 `120.126.10.41`。

## 二、採用的車位形式

本版適用於寬敞、車身已人工對正的直線車位，車尾朝向固定的後牆或擋板。操作者先完成對位，程式再控制直線倒車與後方距離定位。倒車期間舵機保持中立值 152。

依控制台顯示，開始前應滿足：

- 後方測距器至固定反射面的距離為 750～1800 毫米。
- 前、左、右測距均有效且大於 450 毫米，倒車過程也須維持。
- 後方反射面保持固定，且持續位於測距器的量測方向。
- 車身方向已對正；本版不會根據車位線或車身角度修正轉向。

所有距離都是「測距器至反射面」的量測值，不是後保桿至牆面的距離。四向測距僅覆蓋各自視野，不能用來證明整個車身周圍皆無障礙。

## 三、新增操作

1. 用既有 `M` 手動模式將車身對正，車尾朝向車位後牆。
2. 按空白鍵停止，放開空白鍵與方向鍵，等待控制台顯示「待命」。
3. 按 `K` 或點「直線倒車入庫」。車端經既有中立交接後，開始確認距離與 M4 中立回報。
4. 控制台依序顯示準備、直線倒車、到位穩定確認；成功後回待命並顯示完成。

| 操作／情況 | 行為 |
| --- | --- |
| 手動或巡邏中直接按 `K` | 拒絕啟動，提示先停止；不會默默改成停車模式 |
| 停車中按方向鍵 | 不直接控制車輛，電腦端仍只送中立監督心跳 |
| 停車中按 `M` | 中止停車，經中立交接後交回手動；重新按方向鍵才會行駛 |
| 停車中按 `P` | 提示先停止；須回待命後才可開始巡邏 |
| 按空白鍵、控制台失去焦點或關閉 | 沿用原停止要求，中止停車 |
| 距離不符、無進展、逾時或量測異常而中止 | 回待命並保留原因，不自動重試；調整位置後重新按 `K` |
| 通訊、影像、相機資料、ToF 或 M4 保護故障 | 故障待命；原因排除後按 `R`，回待命後再按 `K` |
| 車端主程式因 UART 錯誤結束 | 沿用原流程，排除原因後重新啟動主程式 |

停車時同樣需要控制台保持開啟與焦點，網路及影像接收確認持續正常。重連不會自行恢復倒車。

## 四、停車流程與完成判定

### 準備

全程輸出中立，確認 M4 回報油門與轉向均為 152。後方距離必須在起始範圍內，連續穩定至少 0.5 秒、至少 3 筆真正的新測距，整段最大與最小值差不超過 30 毫米，才開始倒車。3 秒仍無法符合條件便中止。

### 直線倒車

預設倒車命令為電子變速器（ESC）值 150，轉向維持 152；目標後方距離為 600 毫米。這是沿用既有手動控制方向的命令值，不是指定車速。

遇到以下任一狀況便輸出中立並中止：

- 任一方向距離小於或等於 450 毫米。
- 2 秒內未累積接近至少 20 毫米。
- 後距比本次已達到的最近距離增加至少 100 毫米。
- 相鄰兩次後方量測差異大於 250 毫米。
- 倒車階段達 8 秒仍未結束。
- 測距樣本識別異常、時間退行或 M4 重新啟動。

期限先於新資料判斷；已到無進展期限時，即使剛收到距離下降的資料，也不會延長倒車。

### 到位穩定確認

新後方量測到達 600 毫米或以下時，立即改送中立，之後不再補倒車或自動前進修正。完成還必須符合：

- 後距持續在 500～650 毫米之間。
- M4 回報油門與轉向均為中立值 152。
- 至少觀察 0.5 秒、至少 3 筆真正的新測距。
- 穩定觀察期間最大與最小距離差不超過 30 毫米。

超出到位範圍即中止；3 秒內無法穩定也中止。若回中立後繼續滑行至低於 500 毫米，不會誤報完成。完成與中止皆維持中立，距離恢復或持續收到心跳都不會重新倒車。

畫面的「完成」表示上述距離與中立回報條件已符合；車上尚無輪速回授，因此不是量測到車速精確為零。ESC 中立亦不等同於已驗證的主動煞車。

## 五、新量測識別與相容性

原 M4 遙測已帶開機毫秒數與每顆感測器的原始量測年齡。車端新增 `sample_uptime_ms`，由兩者相減還原該筆 ToF 的讀取時刻，再配合 M4 重啟計數辨識新樣本。

同一筆測距可能出現在多個遙測封包；這些封包不會重複累計為多次穩定量測。樣本間隔超過 0.2 秒會清除穩定觀察窗口。M4 32 位元毫秒計數器正常繞回可接受，時間退行或重新啟動會中止。

這些資訊已存在於目前使用的 M4 封包，所以不用改封包格式或重新燒錄。新增決策仍由原唯一 UART 輸出執行緒在控制鎖內呼叫，沒有第二個馬達控制寫入者。

人物警示、巡邏、影像失聯停止、單一實例與串口排他保護均保留。人物辨識不被用來推測後方距離，也沒有在本階段加入雷達方位決策。

## 六、可選設定

原設定檔不必修改。若日後調整停車參數，可在 `sensor_config.json` 最外層合併以下 `parking` 區段，保留其他區段，再重新啟動主程式：

```json
{
  "parking": {
    "reverse_esc": 150,
    "target_rear_mm": 600,
    "arrival_min_mm": 500,
    "arrival_max_mm": 650,
    "start_min_mm": 750,
    "start_max_mm": 1800,
    "clearance_mm": 450,
    "prepare_s": 0.5,
    "prepare_timeout_s": 3.0,
    "settle_s": 0.5,
    "settle_timeout_s": 3.0,
    "stable_span_mm": 30,
    "min_samples": 3,
    "max_reverse_s": 8.0,
    "no_progress_s": 2.0,
    "min_progress_mm": 20,
    "wrong_way_mm": 100,
    "max_step_mm": 250
  }
}
```

倒車命令限制為 148～151。距離門檻須符合「400 ≤ 四向淨空 < 到位下限 ≤ 目標 ≤ 到位上限 < 起始下限 ≤ 起始上限」。參數在啟動時檢查，單改目標時也要保持其餘範圍一致。

若顯示「倒車無進展」，表示未從測距確認足夠的持續接近，可能包含車子沒有移動。程式會中止，不會自行加大油門，也沒有加入特定 ESC 的反覆油門解鎖程序。

## 七、驗證與完成範圍

239 項軟體測試通過，包含前版回歸測試、新測距識別、停車規劃器、模式交接、電腦操作及真實本機 UDP／模擬 UART 整合。完整整合案例驗證了「K 啟動 → 準備 → 倒車 → 到位穩定 → 完成待命」，以及倒車途中空白鍵取消後不再輸出倒車命令。

新增測試亦涵蓋重複樣本、M4 時間繞回與重啟、無進展期限、到位後超出範圍、感測失效、影像失聯、舊模式封包及重新連線不恢復。

已檢查 Python 3.8 語法及與前版保留檔案的合併載入。尚未在你的 Jetson、Windows 圖形介面或實車上驗證本次停車功能。

本版完成範圍為人工對正後的直線倒車距離定位。後續仍可擴充車位搜尋與轉向對位；既定待辦還有開機自動啟動及展示紀錄。
